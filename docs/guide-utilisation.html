1Présentation

Ce que fait la boutique, pour qui, et dans quels environnements.

Glowing Cosmetics est une boutique en ligne de cosmétiques (soins du visage, maquillage, soins capillaires, parfums, soins du corps) avec un back-office complet. La boutique fonctionne en franc CFA (FCFA), avec des prix sans décimales, et en français par défaut (un sélecteur FR/EN est disponible sur la boutique).

Boutique

Vendre sans friction

Catalogue filtrable, fiche produit détaillée, panier, favoris, commande possible sans créer de compte.

Paiements

Cinq moyens, activables

Mobile money (MoneyFusion), carte bancaire, PayPal, virement bancaire, paiement à la livraison.

Back-office

Tout piloter au même endroit

Commandes, produits, catégories, coupons, bannières, avis, messages, newsletter et campagnes.

Connexion

Trois façons d'entrer

Mot de passe, code à usage unique par e-mail, code à usage unique par SMS. Aucune inscription obligatoire pour acheter.

Les deux environnements

Trois façons de se connecter (clients)

  1. E-mail + mot de passe — le formulaire classique de /login.
  2. Code par e-mail — /login/email : on saisit son adresse, on reçoit un code à 6 chiffres valable quelques minutes, on le saisit. Aucun mot de passe à retenir.
  3. Code par SMS — /login/sms : on saisit son numéro ; si le numéro est déjà connu et vérifié, un code part par SMS ; sinon la page d'activation demande e-mail, mot de passe et numéro pour lier le compte.

Le mot de passe oublié reste disponible via /forgot-password (lien reçu par e-mail). Si Google/Facebook sont configurés, les boutons de connexion sociale apparaissent également.

3Parcours visiteur

De la page d'accueil à la commande, sans compte.

Accueil→Catalogue / filtres→Fiche produit→Panier→Commande (invité)→Confirmation

3.1 Accueil et boutique

  • Accueil : bannière (slider), catégories, produits mis en avant, section « offre limitée » si une date de fin est configurée, inscription newsletter.
  • Template d'accueil : la présentation dépend du réglage Apparence — Classique ou Glowing Beauty. Les produits, prix, panier et paiement restent identiques.
  • Boutique (/shop) : recherche par mot-clé, filtre par catégorie et par tag, prix minimum/maximum, produits en promotion uniquement, produits épuisés inclus ou non, capacité/format, tri.
  • Fiche produit (/products/…) : galerie d'images, prix et prix promotionnel, stock, formats disponibles, onglets d'informations (utilisation, ingrédients, précautions, conservation), avis approuvés, ajout au panier et aux favoris, aperçu rapide.

3.2 Panier et favoris

  • Le panier est conservé en session : le visiteur peut modifier les quantités, retirer une ligne ou vider le panier.
  • La liste de favoris existe aussi sans compte (session). Une fois connecté, elle est rattachée au compte. Le réglage Liste de souhaits peut la désactiver.
  • Les compteurs du panier et des favoris se mettent à jour dans l'en-tête sans recharger la page.

3.3 Contact, newsletter, pages d'information

  • Contact (/pages/contact) : le message arrive dans Back-office → Messages ; le compteur de non-lus s'affiche dans la barre latérale.
  • Newsletter : inscription depuis le pied de page ; désinscription par lien personnel reçu par e-mail.
  • Pages : À propos, FAQ, politique de confidentialité, conditions générales.
Avis clientsUn avis déposé sur une fiche produit n'est visible qu'après validation dans le back-office. Il faut être connecté pour déposer un avis, et le dépôt est limité en fréquence.

4Compte client

Tableau de bord, commandes et profil.

4.1 Tableau de bord

/account/dashboard affiche un récapitulatif : nombre de commandes, commandes en attente, commandes livrées, total payé, puis les dernières commandes avec leur statut et un lien « Voir ».

4.2 Commandes

  • Mes commandes : liste de toutes les commandes du compte, avec statut, paiement et montant.
  • Détail : articles, quantités, adresses, mode de paiement, statut, suivi éventuel (transporteur et numéro de suivi renseignés par l'administrateur).
  • Annulation : possible uniquement tant que la commande est En attente. L'annulation remet automatiquement les articles en stock.

4.3 Profil

Le client peut modifier son prénom, nom, e-mail, téléphone, adresse, ville, code postal, pays et avatar, et changer son mot de passe (le mot de passe actuel est demandé). Le changement d'e-mail vérifie l'unicité de l'adresse.

4.4 Connexion sans mot de passe

Les codes à usage unique expirent après quelques minutes. Des limites anti-abus protègent les formulaires : par exemple un même numéro ne peut demander qu'un nombre restreint de codes par heure, avec un délai d'attente entre deux demandes. En cas de blocage, le message indique de patienter.

En devLes e-mails et SMS ne partent pas réellement : les codes sont écrits dans les journaux (storage/logs/laravel.log, visible via docker compose exec app tail -f storage/logs/laravel.log). Ne jamais activer ce comportement en production.

5Commande et paiements

Du panier à l'expédition, avec les cinq moyens de paiement.

5.1 Passer commande

La commande est possible sans compte. L'écran de paiement demande :

  • l'adresse de livraison : prénom, nom, e-mail, téléphone, ville, quartier ;
  • une adresse de facturation distincte si besoin (case « identique à la livraison ») ;
  • un code promo facultatif ;
  • un mode de paiement parmi ceux activés par l'administrateur ;
  • des notes de commande facultatives (1 000 caractères maximum).

Le bouton de validation est protégé contre le double envoi : un double clic ou un rechargement retrouve la commande déjà créée au lieu d'en créer une seconde.

5.2 Les moyens de paiement

MoyenFonctionnement
Mobile money (MoneyFusion)Redirection vers la page de paiement MoneyFusion (Orange Money, MTN, Wave…). La commande reste En attente de paiement jusqu'à la confirmation. Les notifications manquées sont revérifiées automatiquement toutes les 10 minutes.
Paiement à la livraisonCommande enregistrée immédiatement, réglée en espèces à la réception. Un e-mail de confirmation part si l'option est activée.
Virement bancaireCommande enregistrée ; les instructions sont communiquées et l'administrateur marque le paiement Payé à réception.
Carte bancaireMode proposé au paiement (selon la configuration de la passerelle).

Un interrupteur par moyenSeuls les moyens activés dans Réglages → Paiement apparaissent au client, et le serveur refuse de toute façon une commande envoyée avec un moyen désactivé.

5.3 Statuts

Statut de commandeStatut de paiement
En attente — reçue, pas encore préparée (annulable par le client)En attente — rien encaissé
En préparation — en cours de préparationPayé — encaissé (confirmation + facture envoyées)

Chaque changement de statut de commande peut déclencher un e-mail au client (la notification d'expédition peut être coupée dans les réglages). Passer un paiement à Payé envoie la même confirmation, avec facture, qu'un paiement par passerelle.

5.4 Codes promo

Un coupon s'applique à l'étape du paiement. Il peut être en pourcentage ou en montant fixe, avec un panier minimum, un plafond de remise, une période de validité et un nombre d'utilisations maximum. Un code invalide ou expiré affiche un message et n'empêche pas de commander.

6Back-office

Les onze écrans de gestion, dans l'ordre de la barre latérale.

NavigationLa barre latérale groupe les écrans : Ventes (commandes, clients), Catalogue (produits, catégories, avis), Marketing (coupons, bannières, newsletter, campagnes), Support (messages), Paramètres. Le compteur de messages non lus apparaît à côté de « Messages ».

6.1 Tableau de bord

Vue d'ensemble en un écran : revenus du mois, nombre de commandes, produits actifs, clients, puis le panneau À traiter (commandes en attente, avis à modérer, messages non lus, produits en stock bas), le graphique des revenus sur six mois, les commandes récentes et les meilleures ventes.

  • Le seuil de « stock bas » se règle dans Réglages → Boutique.
  • Un clic sur une ligne du panneau « À traiter » ouvre directement la liste concernée.

6.2 Commandes

  • Liste : filtres par statut, paiement, recherche ; export CSV de la sélection ; actions groupées (changement de statut, vérification des paiements en attente).
  • Détail d'une commande : articles et variantes, adresses, coupon, notes, historique ; changements de statut de commande et de paiement ; champs de suivi (transporteur, numéro, lien) ; bouton Vérifier le paiement pour interroger MoneyFusion ; facture PDF téléchargeable.
  • Effets automatiques : annuler remet le stock en vente ; rouvrir une commande annulée le réserve à nouveau ; un changement de statut envoie l'e-mail correspondant (sauf notification d'expédition désactivée).
Paiement marqué « Payé » à la mainRéservé aux encaissements constatés (virement, espèces). Cela déclenche la confirmation et la facture, comme un paiement par passerelle.

6.3 Produits

Liste avec recherche, filtres catégorie et statut, prix, stock, note moyenne. Le formulaire de création/modification est organisé en panneaux :

PanneauContenu
PrésentationNom, référence (SKU), description courte (sous le prix), description complète.
Informations produitCinq onglets de la fiche : utilisation, ingrédients (liste INCI), ingrédients clés, précautions d'emploi, conditions de conservation. Un onglet vide n'apparaît pas.
Prix et stockPrix de vente en FCFA, prix promotionnel, pourcentage de réduction calculé automatiquement, quantité en stock.
PublicationStatut (actif/inactif), mise en vedette sur l'accueil.
Catégories / TagsClassement dans une ou plusieurs catégories, tags de filtre (texture, besoin, actif…).
ImagesEnvoi multiple (JPEG, PNG, WEBP, 2 Mo maximum par image) ; la première image est l'image principale.

La suppression d'un produit est définitive depuis la liste : préférez le statut Inactif pour le retirer de la vente en gardant son historique.

6.4 Catégories et coupons

Catégories

Nom, catégorie parente (pour une hiérarchie), description, ordre d'affichage, visibilité. Les catégories alimentent le menu de la boutique et les filtres du catalogue.

Coupons

Code, type (pourcentage ou montant fixe), valeur, panier minimum, remise maximale, dates de début et de fin, limite d'utilisation, activation. Actions rapides : dupliquer un coupon, l'activer/désactiver sans le supprimer. Le compteur d'utilisations est visible dans la liste.

6.5 Bannières, newsletter et campagnes

Bannières

Image, titre, sous-titre, description, lien et libellé du bouton, type (Hero, Promotionnel, Catégorie, Produit), emplacement (slider principal, haut, milieu ou bas de page, colonne latérale), ordre, dates de diffusion et visibilité. Un aperçu de l'image choisie s'affiche avant l'enregistrement.

Newsletter

Liste des abonnés, ajout manuel par e-mail, activation/désactivation, export CSV. Un abonné désinscrit reste visible mais ne reçoit plus rien.

Campagnes

Rédaction d'un e-mail en texte brut (sujet + message, retours à la ligne conservés), aperçu, enregistrement en brouillon, envoi puis annulation possible tant que l'envoi n'est pas terminé. L'envoi se fait par petits lots côté serveur (planificateur) ; la liste montre l'avancement (envoyés, échecs).

Prérequis d'envoiUne campagne ne peut être envoyée que s'il existe au moins un abonné actif. L'envoi dépend du bon fonctionnement du planificateur (voir Déploiement).

6.6 Clients, avis et messages

Clients

Recherche par nom ou e-mail, fiche client avec coordonnées et commandes, suppression du compte (impossible pour un compte administrateur).

Avis clients

Modération : approuver, retirer l'approbation, supprimer. Les actions groupées traitent jusqu'à 100 avis à la fois. Seuls les avis approuvés sont visibles sur la boutique.

Messages

Messages du formulaire de contact : marquer lu/non lu (individuellement ou en lot), répondre par e-mail directement depuis le message, supprimer. La réponse envoyée est conservée dans la fiche.

8Déploiement

Installer en local, puis publier en production sans interruption non maîtrisée.

8.1 Installation locale (Docker)

  1. Cloner le dépôt et se placer dans le dossier du projet.
  2. Lancer docker compose up -d --build. Au premier démarrage, le conteneur app crée .env depuis .env.example, installe Composer, génère la clé, migre la base et crée le lien de stockage.
  3. Charger les données de démonstration (facultatif) : docker compose exec app php artisan db:seed.
  4. Construire les assets si nécessaire : docker compose run --rm --no-deps --volume /var/www/html/node_modules node sh -c "npm run build".

webnginxhttp://localhost:8001

dbMySQL 8 (base cosmetics_db, utilisateur cosmetics)localhost:3308
nodeVite (développement des styles)http://localhost:5173

8.2 Préparer la production

  • Serveur Hostinger avec SSH par clé, PHP 8.5 et MySQL ; racine web dans public_html, application dans domains/klab-consulting.com/laravel.
  • Fichier .env de production renseigné : APP_ENV=production, APP_DEBUG=false, APP_URL, base de données, SMTP, Vonage, MoneyFusion (et Google/Facebook si utilisés).
  • Tâche cron hPanel : php artisan schedule:run chaque minute — indispensable aux paiements en attente, aux campagnes newsletter et au nettoyage des codes.
  • Branche main locale propre, à jour avec origin/main ; Docker (ou Node) disponible localement pour construire les assets.
  • Clé SSH autorisée sur le serveur pour le compte de déploiement.

8.3 Publier : scripts/deploy.sh

Toujours commencer par un essai à blanc, qui n'écrit rien :

scripts/deploy.sh --dry-run
scripts/deploy.sh            # déploie origin/main

Le script s'arrête à la première erreur et déroule dans cet ordre :

  1. Contrôles locaux : branche main, arbre propre, identique à origin/main ; construction des assets (public/build) en local, car le serveur n'a pas Node.
  2. Contrôles serveur : SSH, accès à la base, espace disque, arbre Git propre, migrations en attente.
  3. Mode maintenance : php artisan down --retry=60.
  4. Sauvegarde de la base : dump compressé dans ~/backups (droits 600), conservé sur le serveur.
  5. Mise à jour du code : git merge --ff-only, composer install --no-dev, envoi de public/build, copie des assets et des images dans public_html.
  6. Migrations et caches : migrate --force, lien de stockage, reconstruction des caches config/routes/vues, puis php artisan up.
  7. Tests de fumée : /, /shop, /login doivent répondre 200, ainsi que la feuille de style et le script chargés par la page ; contrôle que la tâche planifiée MoneyFusion est visible.
Retour arrièreSi une étape échoue après la mise à jour du code, le script affiche la commande exacte pour restaurer le commit précédent et les assets (public/build.prev). La base n'est pas restaurée automatiquement : en cas de mauvaise migration, réimportez le dump indiqué par le script.

8.5 Après chaque mise en ligne

  • Se connecter au back-office et ouvrir le tableau de bord.
  • Parcourir une fiche produit et ajouter au panier.
  • Simuler une commande (paiement à la livraison) et vérifier l'e-mail de confirmation.
  • Vérifier l'heure de la dernière exécution du cron dans hPanel.
  • Consulter storage/logs/laravel.log sur le serveur pour toute erreur nouvelle.

9Sécurité et sauvegardes

Les règles à ne jamais contourner.

  • Secrets hors Git : .env et les fichiers d'accès (SSH, base, prestataires) ne sont jamais versionnés ni copiés dans un ticket ou un journal de chat.
  • Codes à usage unique : ils ne doivent jamais apparaître en clair dans les journaux de production. Le canal « log » n'est prévu que pour le développement local.
  • Comptes administrateurs : un seul compte par personne, mot de passe long et unique ; la suppression d'un compte administrateur est volontairement impossible depuis l'écran Clients.
  • Paiements : un moyen de paiement ne s'active qu'une fois le compte prestataire opérationnel ; le statut Payé ne se coche qu'à encaissement constaté.
  • Sauvegardes : le déploiement prend un dump avant chaque migration ; conservez également une copie hors serveur (base et storage/app/public) selon votre politique de rétention.
  • Mises à jour : composer/npm et correctifs du serveur sont appliqués par le technicien, puis testés en dev avant déploiement.

10Dépannage

Les incidents les plus fréquents et leur solution.

SymptômeCause probable et solution
Le client ne reçoit pas le code par e-mailVérifier le dossier indésirables, puis les réglages SMTP. En dev, le code est dans storage/logs/laravel.log. Réessayer après le délai anti-abus (60 s par défaut).
Le client ne reçoit pas le code par SMSNuméro inconnu → la page d'activation s'affiche ; suivre ce parcours. Vérifier les clés Vonage et le crédit du compte. En dev, aucun SMS n'est envoyé.

Un paiement MoneyFusion reste « En attente »La notification n'est peut-être pas arrivée. Ouvrir la commande et cliquer Vérifier le paiement ; sinon attendre la vérification automatique (10 minutes). Contrôler que le cron tourne.
Un moyen de paiement n'apparaît pas au paiementIl est désactivé dans Réglages → Paiement ; l'activer.
Un avis client est invisibleIl attend la modération : Avis clients → approuver.
La campagne newsletter ne démarre pasAucun abonné actif, ou planificateur arrêté. Vérifier le cron schedule:run et l'état (brouillon / envoi / envoyée).
« 419 Page expirée » sur un formulaireSession expirée : recharger la page, se reconnecter si nécessaire.
Page sans style après un déploiementLes assets n'ont pas été copiés dans public_html/build. Relancer le script ; vérifier la présence de public/build/manifest.json.
Le site reste en maintenanceExécuter php artisan up sur le serveur.
Une image produit ne s'affiche pasVérifier le lien de stockage (php artisan storage:link) et le format/poids de l'image (2 Mo maximum).
En résuméLe client achète sans compte ; le back-office pilote le catalogue, les promotions et la relation client ; les réglages se font sans toucher au code ; le déploiement est scripté, sauvegardé et vérifié automatiquement.
